# Revisión OWASP del sistema de inteligencia de amenazas

**Fecha:** 3 de septiembre de 2026
**Marcos aplicados:** [OWASP Top 10:2025](https://owasp.org/Top10/2025/0x00_2025-Introduction/) (versión final, enero de 2026) y [OWASP API Security Top 10:2023](https://owasp.org/API-Security/editions/2023/en/0x11-t10/) (edición vigente; no existe una posterior)
**Alcance:** interfaz web Flask (`webui/`), capa HTTP de recolección (`threatintel/http.py`), autenticación y sesiones, exportaciones, dependencias, servidor de aplicaciones
**Método:** cada categoría se probó **ejecutando** un ataque o una medición contra una copia de la base de datos o contra el servicio en marcha. Ningún hallazgo procede de leer código sin comprobarlo.

## OWASP Top 10:2025 — Web

### A01:2025 Broken Access Control *(incluye SSRF desde 2025)*

| Prueba ejecutada | Resultado |
|---|---|
| Rutas `GET` sin sesión | Solo `/login` responde 200 ✅ |
| Usuario `viewer` contra 3 páginas y 5 acciones de administrador | 8/8 denegadas con `403` ✅ |
| Identificadores secuenciales (`/amenazas/1`) | Sistema mono-inquilino: todo usuario autenticado ve todo, por diseño ✅ |
| **SSRF:** «Probar fuente» con `http://127.0.0.1:11434/api/tags` | **❌ Alcanzaba la API de Ollama, `localhost` y la propia interfaz** |
| Redirección abierta `?siguiente=//evil.com/` | ❌ Corregida en la revisión anterior; re-verificada ✅ |

**Corrección SSRF** (`threatintel/http.py`): `validar_destino()` rechaza esquemas distintos de `http`/`https`, nombres reservados y **cualquier dirección a la que resuelva el nombre** dentro de loopback, privadas (10/8, 172.16/12, 192.168/16), link-local (169.254/16, metadatos cloud), multicast, reservadas y sus equivalentes IPv6 — lo que cubre también el *DNS rebinding*. Las redirecciones **ya no se siguen a ciegas**: cada salto pasa por la misma validación antes de solicitarse. Verificado: 6/6 destinos internos bloqueados con `destino_prohibido`, 52/52 feeds legítimos siguen funcionando.

### A02:2025 Security Misconfiguration

| Prueba ejecutada | Resultado |
|---|---|
| **CSP** | **❌ `script-src` y `style-src` llevaban `'unsafe-inline'`** |
| Métodos `TRACE`, `PUT`, `DELETE`, `PATCH` | `405` ✅ |
| Modo depuración de Flask | Desactivado; servidor `waitress` ✅ |
| Cabecera `Server` | `ThreatIntel`, sin versión del servidor ✅ |
| `X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy` | Presentes ✅ |
| Páginas autenticadas cacheables | ❌ Sin `Cache-Control` |

**Corrección CSP.** Se eliminaron los **8 manejadores en línea** (`onclick`, `onsubmit`, `onchange`) y los **100 atributos `style=`** de las 15 plantillas. El comportamiento vive ahora en `static/app.js` mediante atributos `data-toggle`, `data-confirm` y `data-autosubmit`; el estilo, en clases de utilidad de `static/estilo.css`. Las barras de anchura dinámica se expresan como clases `ancho-N` en pasos del 5 %. La política resultante:

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:;
font-src 'self'; connect-src 'self'; form-action 'self'; frame-ancestors 'none';
base-uri 'self'; object-src 'none'
```

Un XSS que lograse inyectar `<script>`, `onclick=` o `style=` queda **bloqueado por el navegador**, no solo por el autoescape. Añadidas `Permissions-Policy` y `Cross-Origin-Opener-Policy`. Las respuestas autenticadas llevan `Cache-Control: no-store, private`.

| Prueba ejecutada | Resultado |
|---|---|

### A06:2025 Insecure Design

| Prueba ejecutada | Resultado |
|---|---|
| **Feed «infinito» servido en local** | **❌ 200 000 entradas, 4 196 MB de RAM, 107 s. Sin límite** |
| Servidor que no responde (*slowloris*) | Cortado a los 5,5 s con `timeout=5` ✅ |
| Bomba de entidades XML | Contenida por feedparser ✅ |
| Fallo de red al enviar correo | Distinguido de fallo de credencial ✅ |

**Corrección** (`threatintel/http.py`): lectura por trozos con tope de **15 MB** (`MAX_BYTES_RESPUESTA`); si `Content-Length` lo supera, ni se empieza a leer. Verificado: el mismo feed hostil se corta en 0,1 s con 15 MB de pico. El feed legítimo más grande del catálogo (MSRC, 4 342 entradas) ronda los 6 MB.

### A07:2025 Authentication Failures

| Prueba ejecutada | Resultado |
|---|---|
| Bloqueo tras 5 intentos fallidos | Funciona ✅ |
| Fijación de sesión | `session.clear()` al iniciar ✅ |
| **Oráculo temporal en el login** | **❌ Usuario existente 188 ms, inexistente 0,1 ms: ratio 1 700×** — enumeración de cuentas |
| **Contenido de la cookie de sesión** | **❌ Usuario, rol, token CSRF y hora de inicio legibles por cualquiera que la capturase** (firmada, no cifrada) |

**Corrección del oráculo:** cuando el usuario no existe se ejecuta bcrypt contra un hash ficticio. Verificado: 188 ms frente a 187 ms, ratio 1,01×.

**Corrección de la cookie: sesiones en servidor.** La cookie contiene ahora **un único identificador aleatorio de 256 bits**; usuario, rol, CSRF, IP y caducidad viven en la tabla `web_sessions`, con el identificador guardado como **hash SHA-256** (leer la tabla no da tokens utilizables). Ventajas que una cookie autocontenida no puede ofrecer: **revocación** — cambiar la contraseña cierra todas las sesiones del usuario (verificado: 2 → 0) — y caducidad controlada en servidor. La cookie pasó de ~330 a 130 caracteres y su contenido decodificado es `{"sid": "…", "_permanent": true}`.

*Sobre el cifrado asimétrico solicitado:* no se ha aplicado a propósito. El mismo proceso emite y verifica la sesión, así que la clave privada residiría en la misma máquina que la pública; sería simétrico en la práctica y solo añadiría complejidad. La sesión opaca en servidor resuelve la exposición de forma más completa. El cifrado asimétrico sí tendría sentido si un **tercer sistema** debiera verificar tokens emitidos por éste sin poder forjarlos; no es el caso hoy.

## OWASP API Security Top 10:2023

La interfaz es HTML servido por Flask, no una API REST pública; las categorías se aplican a las rutas `POST`, a `/salud.json` y al **consumo** de las API externas (NVD, KEV, EPSS).

| Categoría | Prueba | Resultado |
|---|---|---|
| **API1** Broken Object Level Authorization | Ids secuenciales entre usuarios | Mono-inquilino; `viewer` no puede escribir ✅ |
| **API2** Broken Authentication | Oráculo temporal, cookie legible | ❌ **Ambos corregidos** (ver A07) |
| **API3** Broken Object Property Level Authorization | Campos arbitrarios en `actualizar()` | Lista blanca ✅ |
| **API4** Unrestricted Resource Consumption | Feed sin fin; «Probar todas» repetible | ❌ **Tope de 15 MB** + **límite de 1 ejecución / 5 min** en la prueba masiva |
| **API5** Broken Function Level Authorization | 5 acciones de admin como `viewer` | `403` ✅ |
| **API6** Unrestricted Access to Sensitive Business Flows | Rotación de contraseña SMTP | Solo admin, CSRF, verificación previa ✅ |
| **API7** Server Side Request Forgery | Destinos internos desde «Probar fuente» | ❌ **Corregido** (ver A01) |
| **API8** Security Misconfiguration | CSP, cabeceras, `/salud.json` sin token | CSP corregida; `/salud.json` → `403` ✅ |

| **API10** Unsafe Consumption of APIs | Respuestas de NVD/KEV/EPSS | Parseo defensivo con `.get()`; ahora también acotadas a 15 MB ✅ |

## Riesgos aceptados y documentados

| Riesgo | Situación | Mitigación existente |
|---|---|---|
| **HTTP sin TLS** | La cookie de sesión (ahora opaca) y la contraseña de acceso viajan en claro por la LAN | Decisión explícita del responsable; TLS autofirmado disponible bajo demanda. Con la sesión opaca, capturar la cookie ya no revela datos, aunque sí permite suplantar hasta que caduque |
| **`ufw` inactivo** | Puerto 9090 alcanzable desde toda la red interna | Autenticación, bloqueo por intentos, CSRF, sesión revocable |
| **Pin de `stanza`** | `argostranslate` declara 1.10.1; instalada 1.14.0 por CVE | Funcionamiento verificado; revisar al actualizar Argos |

## Lo que esta revisión no cubre

- **Pruebas de penetración externas.** Todo lo ha ejecutado el autor del código. Una segunda mirada independiente encontraría lo que una autorrevisión no ve.
- **Concurrencia de varios operadores.** Solo hay un usuario administrador.
- **Análisis estático de terceros** (Bandit, Semgrep) — no instalados; `pip-audit` sí se ejecutó.
